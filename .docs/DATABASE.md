# Dokumentasi Database SiAbsen

Dokumen ini merupakan spesifikasi **rencana schema PostgreSQL** untuk aplikasi SiAbsen. Runtime aplikasi menggunakan Laravel 13 dan Eloquent. Koneksi `pgsql` tersedia dan dipilih melalui `DB_CONNECTION`; fallback konfigurasi tanpa environment adalah SQLite. DDL rencana domain tersedia di [`QUERY.sql`](QUERY.sql), sedangkan kode diagram untuk dbdiagram.io tersedia pada bagian diagram dalam dokumen ini.

Status implementasi saat ini hanya mencakup model Eloquent `User`. Sembilan tabel domain lainnya, enum Eloquent, relasi akademik, dan alur absensi masih merupakan target rancangan. Migration yang sudah ada tidak digunakan sebagai sumber kebenaran dan tidak menjadi bagian dari perubahan dokumentasi ini.

`QUERY.sql` hanya berisi DDL 10 tabel domain SiAbsen. File tersebut tidak membuat database, role PostgreSQL, tabel internal Laravel, data contoh, atau menjalankan query aplikasi.

## 1. Konvensi Database

- Provider target adalah PostgreSQL; versi server tidak dikunci dalam konfigurasi repository.
- ORM runtime adalah Eloquent; koneksi `pgsql` dipilih melalui `DB_CONNECTION` dan fallback konfigurasi adalah SQLite.
- Semua nama tabel, kolom, constraint, dan index menggunakan `snake_case`.
- Primary key domain menggunakan `BIGINT GENERATED BY DEFAULT AS IDENTITY`, kecuali tabel profil yang menggunakan `user_id` sebagai primary key sekaligus foreign key.
- Nilai waktu menggunakan `TIMESTAMPTZ(6)` dengan presisi mikrodetik.
- `created_at` memiliki default `CURRENT_TIMESTAMP(6)`; `updated_at` tidak memiliki default database dan dikelola oleh Eloquent.
- Boolean menggunakan `BOOLEAN` PostgreSQL dengan default `TRUE` atau `FALSE`.
- Nilai terbatas menggunakan PostgreSQL native enum `user_role` dan `attendance_status`.
- Relasi tidak mendefinisikan `ON UPDATE CASCADE`; primary key domain tidak diubah setelah dibuat.
- Penghapusan profil `users` mengikuti `CASCADE`; relasi akademik, assignment, sesi, dan record mengikuti `RESTRICT`.
- Database runtime menggunakan schema `public`; DDL menetapkan `search_path` ke `public`.
- Unique constraint pada `users.email` sudah menyediakan index untuk pencarian email, sehingga tidak dibuat index email kedua.
- Unique composite `classes (education_level_id, name)` juga melayani pencarian dan foreign key berdasarkan `education_level_id`.
- Suite PHPUnit memakai SQLite in-memory. Konfigurasi test tersebut tidak memvalidasi kompatibilitas DDL PostgreSQL.

## 3. Diagram Relasi

Kode DBML berikut dapat langsung ditempel ke dbdiagram.io. Enum PostgreSQL direpresentasikan sebagai DBML `Enum`, `bigint` dengan `increment` merepresentasikan identity, dan `timestamp` merepresentasikan `TIMESTAMPTZ(6)`. DBML adalah diagram logis dan tidak dapat melakukan round-trip seluruh DDL; partial index, check, dan composite foreign key dijelaskan melalui catatan.

```dbml
Enum user_role {
  STUDENT
  TEACHER
  ADMIN
}

Enum attendance_status {
  HADIR
  TERLAMBAT
  TIDAK_HADIR
}

Table users {
  id bigint [pk, increment]
  name varchar(255) [not null]
  email varchar(255) [not null, unique]
  email_verified_at timestamp
  password varchar(255) [not null, note: "Stores the hashed password"]
  role user_role [not null]
  phone varchar(30)
  birth_date date
  remember_token varchar(100)
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]

  Indexes {
    role [name: "idx_users_role"]
  }
}

Table student_profiles {
  user_id bigint [pk]
  student_number varchar(50) [not null, unique]
  education_level_id bigint [not null]

  Indexes {
    education_level_id [name: "idx_student_profiles_education_level"]
  }
}

Table teacher_profiles {
  user_id bigint [pk]
}

Table education_levels {
  id bigint [pk, increment]
  name varchar(100) [not null, unique]
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]
}

Table classes {
  id bigint [pk, increment]
  name varchar(100) [not null]
  education_level_id bigint [not null]
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]

  Indexes {
    (education_level_id, name) [unique, name: "uq_classes_education_level_name"]
  }
}

Table subjects {
  id bigint [pk, increment]
  name varchar(150) [not null, unique]
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]
}

Table class_students {
  id bigint [pk, increment]
  class_id bigint [not null]
  student_id bigint [not null]
  is_active boolean [not null, default: true]
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]

  Indexes {
    (student_id, is_active) [name: "idx_class_students_student_active"]
    (class_id, is_active) [name: "idx_class_students_class_active"]
  }

  Note: 'PostgreSQL partial unique index: student_id WHERE is_active.'
}

Table teacher_assignments {
  id bigint [pk, increment]
  teacher_id bigint [not null]
  class_id bigint [not null]
  subject_id bigint [not null]
  is_active boolean [not null, default: true]
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]

  Indexes {
    (id, class_id) [unique, name: "uq_teacher_assignments_id_class"]
    (teacher_id, is_active) [name: "idx_teacher_assignments_teacher_active"]
    (class_id, is_active) [name: "idx_teacher_assignments_class_active"]
    (subject_id, is_active) [name: "idx_teacher_assignments_subject_active"]
  }

  Note: 'PostgreSQL partial unique index: teacher_id, class_id, subject_id WHERE is_active.'
}

Table attendance_sessions {
  id bigint [pk, increment]
  assignment_id bigint [not null]
  class_id bigint [not null]
  session_date date [not null]
  start_at timestamp [not null]
  end_at timestamp [not null]
  qr_payload varchar(255) [not null, unique]
  created_by bigint [not null]
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]

  Indexes {
    (assignment_id, session_date, start_at, end_at) [unique, name: "uq_attendance_sessions_assignment_date_time"]
    (assignment_id, start_at, end_at) [name: "idx_attendance_sessions_assignment_time"]
    (class_id, session_date) [name: "idx_attendance_sessions_class_date"]
    created_by [name: "idx_attendance_sessions_created_by"]
  }

  Note: 'PostgreSQL enforces end_at > start_at and class_id must match the referenced assignment.'
}

Table attendance_records {
  id bigint [pk, increment]
  session_id bigint [not null]
  student_id bigint [not null]
  scanned_at timestamp [not null]
  status attendance_status [not null]
  late_minutes int [note: "Nullable and constrained to values greater than or equal to zero"]
  created_at timestamp [not null, default: `CURRENT_TIMESTAMP(6)`]
  updated_at timestamp [not null]

  Indexes {
    (session_id, student_id) [unique, name: "uq_attendance_records_session_student"]
    (student_id, scanned_at) [name: "idx_attendance_records_student_scanned"]
    (session_id, status) [name: "idx_attendance_records_session_status"]
  }

  Note: 'PostgreSQL check: late_minutes IS NULL OR late_minutes >= 0.'
}

Ref: "users"."id" - "student_profiles"."user_id" [delete: cascade]
Ref: "users"."id" - "teacher_profiles"."user_id" [delete: cascade]
Ref: "education_levels"."id" < "student_profiles"."education_level_id" [delete: restrict]
Ref: "education_levels"."id" < "classes"."education_level_id" [delete: restrict]
Ref: "users"."id" < "class_students"."student_id" [delete: restrict]
Ref: "classes"."id" < "class_students"."class_id" [delete: restrict]
Ref: "users"."id" < "teacher_assignments"."teacher_id" [delete: restrict]
Ref: "classes"."id" < "teacher_assignments"."class_id" [delete: restrict]
Ref: "subjects"."id" < "teacher_assignments"."subject_id" [delete: restrict]
Ref: "teacher_assignments"."id" < "attendance_sessions"."assignment_id" [delete: restrict]
Ref: "classes"."id" < "attendance_sessions"."class_id" [delete: restrict]
Ref: "users"."id" < "attendance_sessions"."created_by" [delete: restrict]
Ref: "attendance_sessions"."id" < "attendance_records"."session_id" [delete: restrict]
```

## 4. Detail Struktur Tabel

### 4.1 `users`

Menyimpan akun, data autentikasi, dan role `STUDENT`, `TEACHER`, atau `ADMIN`. Kontrak autentikasi menggunakan `email` dan `password` agar sesuai dengan model Eloquent `User`; kolom `password` selalu menyimpan hasil hash.

| Kolom               | Tipe PostgreSQL  | Null  | Default/Constraint     |
| ------------------- | ---------------- | ----- | ---------------------- |
| `id`                | `BIGINT`         | Tidak | Identity, primary key  |
| `name`              | `VARCHAR(255)`   | Tidak | Wajib diisi            |
| `email`             | `VARCHAR(255)`   | Tidak | Unique                 |
| `email_verified_at` | `TIMESTAMPTZ(6)` | Ya    | Waktu verifikasi email |
| `password`          | `VARCHAR(255)`   | Tidak | Hash password          |
| `role`              | `user_role`      | Tidak | Wajib diisi            |
| `phone`             | `VARCHAR(30)`    | Ya    | —                      |
| `birth_date`        | `DATE`           | Ya    | —                      |
| `remember_token`    | `VARCHAR(100)`   | Ya    | Token remember me      |
| `created_at`        | `TIMESTAMPTZ(6)` | Tidak | `CURRENT_TIMESTAMP(6)` |
| `updated_at`        | `TIMESTAMPTZ(6)` | Tidak | Dikelola Eloquent      |

Kolom `role` sudah menjadi bagian target schema, tetapi model `User` saat ini belum memiliki enum cast atau helper untuk domain peran. Model domain harus menggunakan role secara eksplisit agar registrasi, otorisasi, dan penugasan dapat diimplementasikan dengan aman.

Relasi: satu user dapat memiliki maksimal satu `student_profiles`, satu `teacher_profiles`, banyak `class_students`, banyak `teacher_assignments`, banyak `attendance_sessions`, dan banyak `attendance_records`.

## 5. Enum PostgreSQL

### `user_role`

Nilai yang diperbolehkan pada `users.role`:

- `STUDENT`
- `TEACHER`
- `ADMIN`

### `attendance_status`

Nilai yang diperbolehkan pada `attendance_records.status`:

- `HADIR`
- `TERLAMBAT`
- `TIDAK_HADIR`

Menurut aturan domain, record yang dibuat oleh scan hanya menggunakan `HADIR` atau `TERLAMBAT`. `TIDAK_HADIR` dihitung pada saat history atau report dibaca untuk siswa aktif pada kelas sesi yang belum memiliki record. Karena itu, enum tetap menyediakan nilai tersebut untuk kontrak domain, tetapi tidak boleh dibuat oleh alur scan.

Kedua enum tersebut harus memiliki representasi atau cast yang konsisten pada Eloquent ketika domain mulai diimplementasikan.

## 8. Aturan Integritas Absensi

Aturan berikut merupakan kontrak target dan belum diimplementasikan pada service aplikasi:

1. Jendela scan adalah `start_at - 15 menit` sampai `end_at`.
2. Scan dari awal jendela sampai `start_at + 15 menit` menghasilkan `HADIR` dengan `late_minutes` nol.
3. Scan setelah `start_at + 15 menit` sampai `end_at` menghasilkan `TERLAMBAT` dengan selisih menit keterlambatan.
4. Scan di luar jendela ditolak tanpa membuat record.
5. Unique constraint `(session_id, student_id)` memastikan paling banyak satu record untuk setiap pasangan sesi dan siswa. Service harus menangani konflik secara eksplisit, misalnya dengan `ON CONFLICT DO NOTHING` lalu membaca record yang sudah ada, agar scan berulang tetap idempoten.
6. Sesi dengan assignment, tanggal, dan pasangan waktu yang sama ditolak oleh unique constraint.
7. `TIDAK_HADIR` tidak dibuat oleh scan; nilainya dihitung saat pembacaan.
8. Check `end_at > start_at` dan composite foreign key `(assignment_id, class_id)` sudah ditegakkan database. Konsistensi role terhadap profile dan authorization tetap harus divalidasi pada service.
9. Partial unique index `class_students (student_id) WHERE is_active` memastikan satu siswa hanya memiliki satu membership aktif. Perubahan membership harus dilakukan secara atomik agar tidak melanggar index tersebut.
10. Partial unique index `teacher_assignments (teacher_id, class_id, subject_id) WHERE is_active` memastikan hanya satu assignment aktif untuk kombinasi guru, kelas, dan mata pelajaran.

## 9. Timezone dan Tanggal

- Semua nilai `TIMESTAMPTZ(6)` menyimpan instants yang dapat dikonversi ke zona waktu penyajian.
- Eloquent dan konvensi aplikasi menggunakan UTC; provisioning PostgreSQL sebaiknya memastikan timezone sesi PostgreSQL juga UTC agar output konsisten.
- `session_date` adalah kolom `DATE` dan ditafsirkan sebagai tanggal kalender pada timezone sekolah. Target default aplikasi adalah `Asia/Jakarta` dan harus dapat dikonfigurasi saat service absensi diimplementasikan.
- `start_at`, `end_at`, dan `scanned_at` dikonversi ke timezone sekolah pada service dan batas response API.
- Waktu scan selalu berasal dari server dan tidak mempercayai timestamp client.

## 10. Menjalankan DDL PostgreSQL

`.docs/QUERY.sql` adalah DDL transaksional untuk 10 tabel domain pada database PostgreSQL yang sudah dibuat dan dipilih. File tersebut tidak membuat database, role PostgreSQL, tabel internal Laravel, atau data awal.

Prasyarat:

- PostgreSQL sudah dapat diakses melalui `psql`.
- Database dan schema `public` sudah dibuat.
- User PostgreSQL memiliki izin membuat type, table, constraint, dan index.
- Type atau tabel dengan nama yang sama belum ada; DDL sengaja gagal cepat jika objek tersebut sudah ada.
- Model Eloquent domain dan tabel internal Laravel sudah disiapkan sebelum DDL digunakan pada database aplikasi aktif.

Contoh eksekusi dari root repository:

```bash
psql --set=ON_ERROR_STOP=1 --dbname=<nama_database> --file=.docs/QUERY.sql
```

Perintah tersebut hanya menjalankan isi DDL. `QUERY.sql` tidak menyediakan tabel `password_reset_tokens`, `sessions`, `cache`, `cache_locks`, `jobs`, `job_batches`, atau `failed_jobs`, meskipun konfigurasi runtime dapat menggunakan tabel tersebut.

## 11. Database Test

PHPUnit dikonfigurasi memakai SQLite in-memory untuk test otomatis:

- Driver: `sqlite`
- Database: `:memory:`
- Session dan cache: storage in-memory
- Queue: `sync`

Karena perbedaan tipe dan constraint PostgreSQL, DDL PostgreSQL harus diuji pada instance PostgreSQL terpisah melalui integration test sebelum diterapkan ke database aplikasi.

## 12. Kebijakan Perubahan Schema

1. Perlakukan `.docs/QUERY.sql` sebagai target DDL untuk 10 tabel domain.

5. Perbarui `.docs/QUERY.sql`, kode DBML, dan `.docs/DATABASE.md` secara bersamaan ketika kolom, enum, constraint, index, atau relasi berubah.

7. Catat keputusan produk atau perubahan aturan database sebelum menerapkan perubahan yang belum diputuskan.
